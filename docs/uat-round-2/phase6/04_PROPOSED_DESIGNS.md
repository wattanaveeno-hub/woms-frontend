# 04 — PROPOSED DESIGN สำหรับหน้าที่ยังไม่มี design

วันที่: 2026-11-14 · สถานะทุกหน้าในเอกสารนี้: **PROPOSED DESIGN — ยังไม่ได้รับอนุมัติจากลูกค้า**

เอกสารนี้เป็น spec สำหรับ 13 route ใน frontend ที่ไม่มีหน้า design ตรงตัวใน artifact `5YaUhXmt8obamZVwDCyZSD` (ดู 03 ส่วน B) จุดประสงค์คือให้ทีมและลูกค้ามีภาพเดียวกันก่อนจะปรับหน้าตา **รอบนี้ไม่ได้แก้โค้ดของ 13 หน้านี้** เพราะทุกหน้าใช้งานได้อยู่แล้ว และการปรับ layout ควรรอลูกค้าอนุมัติ spec ก่อน

หลักที่ใช้กับทุกหน้า
- ไม่เปลี่ยน workflow, permission, กฎธุรกิจ, API หรือ URL ที่มีอยู่ — spec อธิบายเฉพาะการจัดวางและ state
- ใช้คำเรียกเดียวกับระบบปัจจุบัน (ใบงาน, ใบวางบิล, คู่ค้า, ใบเสนอราคา, Revision)
- ใช้ component ที่มีอยู่: `WomsPageHeader`, `WomsSearchBar`, `WomsViewPills`, `WomsDataTable`, `WomsPermissionGate`, `StatusBadge`, `DocLetterhead`, `Toast`, `Dialog`, `NumberInput` (ใหม่ในรอบนี้) — ไม่เพิ่ม library
- ใช้ token สี/ระยะจาก `project/ds/entech/tokens.json` และ `app.css` ของ design เดิม (เขียว `#1b5e37` เป็นสีหลัก, chip สถานะตาม `c-open`/`c-done`/`c-warn`)
- Breakpoint: desktop ≥ 900px, tablet 600–899px, mobile < 600px (ทดสอบที่ 390px)

## 0. Pattern กลาง (ใช้ซ้ำในทุกหน้า)

### 0.1 โครงหน้า

```
Desktop                                          Mobile (<600)
┌─────────────────────────────────────────────┐  ┌──────────────────────┐
│ ← กลับไป...                                  │  │ ← กลับ               │
│ H1 ชื่อหน้า  [chip สถานะ]      [ปุ่มรอง][ปุ่มหลัก]│  │ H1 (ตัดคำ 2 บรรทัด)    │
│ sub: บริบท 1 บรรทัด                          │  │ chip สถานะ            │
├─────────────────────────────────────────────┤  │ sub                  │
│ เนื้อหา (card)                               │  ├──────────────────────┤
│                                             │  │ เนื้อหาเรียงเป็นคอลัมน์เดียว│
└─────────────────────────────────────────────┘  │ ...                  │
                                                 ├──────────────────────┤
                                                 │ แถบปุ่มติดล่าง (sticky) │
                                                 └──────────────────────┘
```

- ปุ่มหลักอยู่ขวาสุดบน desktop และย้ายไปแถบติดล่างบน mobile
- ปุ่มที่ผู้ใช้ไม่มีสิทธิ์ **ไม่แสดง** (ไม่ใช่แสดงแบบ disabled) ยกเว้นกรณีที่ต้องบอกเหตุผล เช่น "แก้ไม่ได้เพราะบิลอนุมัติแล้ว"

### 0.2 State มาตรฐาน

| State | การแสดงผล |
|---|---|
| Loading | skeleton ตามโครงหน้า (หัว + 3 แถว) ไม่ใช้ spinner เต็มจอ |
| Empty | ไอคอน + ข้อความบอกว่ายังไม่มีอะไร + ปุ่มสร้างรายการแรก (แสดงเฉพาะผู้มีสิทธิ์สร้าง) |
| Error (โหลด) | card สีแดงอ่อน: "โหลด…ไม่สำเร็จ" + ปุ่ม "ลองใหม่" ไม่ล้างข้อมูลที่กรอกค้าง |
| Error (บันทึก) | Toast แดง + ไฮไลต์ field ที่ผิดจาก response 400 คงค่าที่กรอกไว้ |
| ไม่มีสิทธิ์ | `WomsPermissionGate`: "คุณไม่มีสิทธิ์เข้าหน้านี้" + ปุ่มกลับหน้าหลัก |
| บันทึกสำเร็จ | Toast เขียว แล้ว redirect ไปหน้ารายละเอียด |

### 0.3 Numeric field

ทุกช่องตัวเลขใช้ `NumberInput` (ดู 02_NUMERIC_INPUT_AUDIT.md)
- ช่องว่างแสดง placeholder `0`
- พิมพ์ 50000 ได้ 50000 ไม่มีศูนย์นำหน้า
- `inputMode` เป็น `numeric` หรือ `decimal` ตามชนิดค่า
- ค่าที่บันทึกไว้เป็น 0 จริงแสดง `0` (`zeroAsEmpty={false}`)
- ช่องบังคับที่ว่าง ให้ validation แจ้ง "กรุณากรอก…" — ไม่แทนค่าเป็น 0 เอง

## 1. `/bills/new` — ทำรายการวางบิล

- **หน้าที่:** ช่างหรือแอดมินสร้างใบวางบิลจากใบงานที่ปิดแล้ว ประกอบด้วยค่าบริการรายเครื่อง (Job Machine) และค่าใช้จ่ายร่วมหนึ่งชุดต่อใบงาน
- **Workflow ที่คงไว้:** เลือกใบงาน → เลือก Job Machine → กรอกค่าบริการ → กรอกค่าใช้จ่ายร่วม → บันทึกร่าง หรือส่งตรวจ (`BillMachineForm` เดิม)
- **Desktop:** 2 คอลัมน์ (8/4)
  - ซ้าย มี 3 card เรียงลงมา
    1. "ใบงาน" — autocomplete เลขใบงาน แสดงลูกค้าและวันที่ปิด
    2. "ค่าบริการรายเครื่อง" — ตาราง เครื่อง | รอบ | ค่าบริการ | หมายเหตุ
    3. "ค่าใช้จ่ายร่วม" — ค่าเดินทาง, กม., จอดรถ, คนยก, อื่น ๆ
  - ขวา มี card "สรุปยอด" แบบ sticky แสดงรวมค่าบริการ, รวมค่าใช้จ่ายร่วม และยอดรวมสุทธิ ใต้ card มีปุ่ม "บันทึกร่าง" และ "ส่งตรวจ"
- **Mobile:** card เรียงคอลัมน์เดียว ตารางเครื่องเปลี่ยนเป็น card ต่อเครื่อง สรุปยอดย้ายเป็นแถบติดล่าง (ยอดสุทธิ + ปุ่มส่งตรวจ) ส่วน "บันทึกร่าง" อยู่ในเมนู ⋯
- **Validation:**
  - ต้องเลือกใบงานและอย่างน้อย 1 เครื่อง
  - ค่าเงินต้อง ≥ 0, ทศนิยมไม่เกิน 2 ตำแหน่ง
  - กม. เป็นจำนวนเต็ม
  - กติกาอื่นใช้ตาม validation เดิมของ `BillMachineForm` และ API (แสดงข้อความจาก API ตรง ๆ)
- **Role:** ใช้สิทธิ์เดิมของหน้า (`WomsPermissionGate`) ผู้ไม่มีสิทธิ์เห็น state "ไม่มีสิทธิ์"
- **Empty:** ไม่มีใบงานที่ปิดแล้วให้เลือก → "ยังไม่มีใบงานที่ปิดแล้วและยังไม่วางบิล"

## 3. `/bills/[id]/print` — พิมพ์ใบวางบิล

- **หน้าที่:** หน้าพิมพ์ A4 ของบิลที่อนุมัติแล้ว

- **Layout หน้าจอ:**
  - แถบเครื่องมือด้านบน (ไม่ออกในงานพิมพ์): ← กลับ | "พิมพ์ครั้งที่ n" | ปุ่ม "พิมพ์" หรือ "พิมพ์ซ้ำ"

- **ส่วนของกระดาษ:**
  - หัวบริษัท
  - ข้อมูลช่างผู้วางบิลและช่วงวันที่
  - ตาราง: ช่าง | รอบ | ใบงาน | เครื่อง | ค่าบริการ
  - ตารางค่าใช้จ่ายร่วม
  - ยอดรวมสุทธิ
  - ช่องลงนาม: ช่างผู้วางบิล / ผู้อนุมัติ / ฝ่ายบัญชี
- **Mobile:**
  - กระดาษย่อให้พอดีความกว้าง (scale) แทนการ reflow เพื่อให้ตรงกับงานพิมพ์
  - ปุ่มพิมพ์อยู่ในแถบติดล่าง
- **Role:** ปุ่มพิมพ์ที่เปลี่ยนสถานะแสดงเฉพาะผู้มี `bill:review`
- **Error:** บันทึกการพิมพ์ไม่สำเร็จ → Toast แดง ไม่เปิดหน้าต่างพิมพ์
