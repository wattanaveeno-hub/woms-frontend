## รายละเอียดต่อหน้า

### ServiceQueueNew
สิ่งที่แก้ (`QueueForm.tsx`, `service-queue/new/page.tsx` — เปลี่ยนเฉพาะการแสดงผล):
- การ์ดเดียวแบ่ง section เส้นบาง + คอลัมน์ขวา “หลังส่งคำขอ”
- ส่วน “วางข้อความจากลูกค้า (ไม่บังคับ)” พื้นเทา มีช่องวางและปุ่ม “เติมจากข้อความ” ในหน้า (เดิมเป็น dialog) — ใช้ parser และกติกาเติมช่องว่างชุดเดิม (`parseJobText` + `queueFillFromPaste`)
- ป้ายอยู่เหนือช่อง · ลำดับ ลูกค้า → เครื่องที่ต้องไป (ตาราง) → ต้องการให้ช่างทำอะไร (tile) → รูปหน้างาน → savebar
- ประเภทงานเป็น tile (radio) · ติดตั้งเลือกเช่า/ขาย/เช่าซื้อด้วย toggle (testid `install-subtype` เดิม)
- ปุ่มส่ง “ส่งคำขอคิว” · หัวรอง “เซลล์ส่งคำขอ แอดมินจัดช่างและนัดลูกค้าให้”

ข้อยกเว้น (คงกติกาธุรกิจ):
- ไม่มีส่วน “ลูกค้าสะดวกเมื่อไร” — QUE-02 v2 ตัดวัน/เวลาที่ลูกค้าต้องการออก (วันนัดมาจากช่างเสนอ → Admin รับ → ลูกค้าคอนเฟิร์ม)
- ประเภทงานแสดงตาม master (8 ประเภท) ไม่ใช่ 4 tile ของ design · คงช่อง ประเภทลูกค้า / เซลล์เจ้าของงาน / ผู้ติดต่อ / ลิงก์ Map ที่ระบบใช้

### JobNew
สิ่งที่แก้ (`JobForm.tsx`, `jobs/new/page.tsx`, `JobEquipmentSection.tsx`):
- 4 ขั้นเป็นการ์ดแยก ป้ายเลขขั้น 1–4 (✓ เมื่อกรอกครบ) · ขั้นแรกที่ยังไม่ครบมีกรอบเขียว
- ขั้น 1 ลูกค้า: ลูกค้า/สาขา, ที่อยู่ติดตั้ง (แก้ได้เฉพาะงานนี้), ผู้ติดต่อ, เบอร์, Map, เซลล์ผู้รับผิดชอบ, ประเภทลูกค้า
- ขั้น 2 งานอะไร: tile ประเภทงาน · ติดตั้งแบบ (toggle) · ซ่อมถอน (ประเภทย่อย) · อ้างอิงงานเดิม/เหตุผล · ชื่องาน · หมายเหตุ
- ขั้น 3 นัดวันไหน ใครไป: วันนัด เวลา ทีมช่าง ช่างผู้รับผิดชอบ
- ขั้น 4 เครื่องในงานนี้ (การ์ดเดิม + ป้ายขั้น)
- การ์ด “สรุปใบงาน” ขวามีปุ่ม “เปิดงาน” (submit ฟอร์มเดิมด้วย `form="job-form"`) และ “บันทึกร่าง” · หน้าแก้ไขใบงาน `/jobs/[id]/edit` ยังใช้ปุ่มท้ายฟอร์มเหมือนเดิม
- กติกาตรวจก่อนส่ง/ร่าง/idempotency/การวางข้อความ LINE ไม่เปลี่ยน

ข้อยกเว้น:
- ไม่มีช่องช่วงเวลา (slot) และรายชื่อช่างว่างพร้อมระยะทาง — ระบบไม่มีข้อมูลระยะทาง/slot ต่อวัน (ไม่สร้าง UI ที่ไม่มีข้อมูลรองรับ) ใช้ช่องวัน/เวลา + ทีม + ช่างผู้รับผิดชอบเดิม
- ไม่มี “ผูกสัญญาเช่า” ระดับใบงาน — สัญญาผูกรายเครื่องในขั้น 4 (FB-07)
- ไม่มี checkbox “แจ้งเตือนช่างทันทีที่เปิดงาน” — ระบบแจ้งเตือนตามกติกาเดิม ไม่มีตัวเลือกนี้ใน API

### JobDetail
สิ่งที่แก้ (`jobs/[id]/page.tsx`, `JobDetailCards.tsx`):
- ปุ่มหัวหน้า: “พิมพ์ใบงาน (PDF)” · แก้ไขรายละเอียด · แชท/ส่งงาน · ปุ่มหลัก “ตรวจและปิดงาน” (เปิดแท็บปิดงาน ตรวจหลักฐานตามเดิม)
- คอลัมน์ขวา: การ์ด “ลูกค้า & หน้างาน” + ปุ่ม โทร / เปิดแผนที่ · การ์ด “เครื่องในงาน” (สรุป 5 เครื่อง + ปุ่มดูทั้งหมด) · เส้นทางของใบงาน (ย้ายจากแท็บภาพรวม)
- ทุก action เดิมยังอยู่ (workflow รับทราบ/เริ่ม/พัก/เลื่อน/ยกเลิก, รายรับ-ค่าใช้จ่าย, คิวช่าง/เลื่อนงาน, แท็บเครื่อง/ปิดงาน/อะไหล่) — ทดสอบ flow4 ผ่าน

ยังต่าง (FAIL):
1. แท็บภาพรวมของ design มี checklist “หลักฐานปิดงาน” (รูป/ป้าย SN/ลายเซ็นลูกค้า/ลายเซ็นช่าง) และ “บันทึกจากช่าง” — ต้องใช้ข้อมูลสรุปรูปรายเครื่อง (`/photos/summary`) และผลรายเครื่องมาประกอบ ยังไม่ได้ทำในรอบนี้เพื่อไม่แตะ flow ปิดงาน
2. design มีแท็บ “ประวัติ” และ “ใบเสนอราคาที่ผูก” ในคอลัมน์ขวา — ข้อมูลใบเสนอราคาอยู่ในแท็บอะไหล่ & การเงิน (JobFinanceCard) ตามสิทธิ์ finance:view

### ServiceQueueDetail
ทดสอบด้วยคิวที่สร้างใหม่ใน sandbox (เซลล์ขอ → Admin จัดช่าง → ช่างเสนอ → Admin รับคิว = รอลูกค้าคอนเฟิร์ม)
สิ่งที่แก้ (`service-queue/[id]/page.tsx`, `serviceQueueRules.ts`):
- หัวเรื่อง = ชื่องาน + ป้าย JN + สถานะ · บรรทัดรอง เลขคิว · ประเภท · ขอโดย · เวลา · รอบนัด
- แถบ “ขั้นของคิว” 6 ขั้น (ขอคิว → จัดช่าง → ช่างตอบรับ → Admin รับคิว → ลูกค้ายืนยัน → Admin เปิด JN / ส่งงานเดิมกลับ) อ่านจากสถานะ + Log (`queueSteps()` มี unit test 2 ข้อ)
- การ์ด “นัดที่เสนอให้ลูกค้า” (วันเวลา · ช่าง · รอบนัด) กรอบเขียวเมื่อรอ Admin รับ/รอลูกค้า
- คอลัมน์ขวา “ความเคลื่อนไหว · Log” แบบ timeline (ข้อมูลเดิมครบ) · ช่างไม่เห็น Log (TECH-02 เดิม)

ข้อยกเว้น:
- ปุ่มดำเนินการ (ลูกค้าคอนเฟิร์มแล้ว / ขอคิวใหม่ / เปลี่ยนช่าง / แก้ไข / ยกเลิก / เปิด JN) อยู่แถบเดียวด้านบนตาม `queueButtons()` เดิม ไม่ทำปุ่มซ้ำในการ์ดนัด
- ไม่มี “ระยะจากงานก่อนหน้า” และปุ่ม “เปิดในแชทกลุ่ม” ระดับหัวหน้า (ลิงก์ “เปิดในแชท” อยู่รายข้อความในส่วนบทสนทนา)

### Main (/dashboard) → Reports
- หน้าหลักเหลือ: ทักทาย, KPI 4 ช่อง, “ต้องจัดการตอนนี้”, ทีมช่างวันนี้ + ปุ่ม “รายงาน & ส่งออก” และ “ดูปฏิทินช่าง” (ตรง design)
- ย้ายไป `/reports` (หน้าใหม่ “รายงาน & ส่งออก”): ภาพรวมทั้งหมด (stat cards + ลิงก์กรอง), งานบำรุงรักษาและสิ่งที่ต้องตามต่อ, เครื่องที่ต้องทำ PM, กราฟ, “สรุปผล” + ตัวกรอง + Export Excel — โค้ดย้ายมาทั้งชุด (`DashboardOverview.tsx`) ใช้ `dashboardFetchPlan` เดิม จึงเรียก API/แสดงตามสิทธิ์เหมือนเดิม
- เมนู: `/reports` เพิ่มใน navMenu (perm `dashboard:view`, ไม่ใช่ sales, ไม่อยู่ในแถบข้างตาม design) · เข้าได้จากปุ่มบนหน้าหลัก
- ทดสอบ (flow12): admin และ manager — หน้าหลักไม่มีส่วนสรุป, /reports แสดงครบ, Export Excel ได้ไฟล์ `.xlsx`, ลิงก์กรอง 8 ลิงก์ยังอยู่, ไม่มี error
- ไม่มีข้อมูลถูกลบ ไม่มี API เปลี่ยน
