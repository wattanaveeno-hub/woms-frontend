### 1. D-07B — จับคู่รุ่นของเครื่องเดิม และย้ายข้อมูลจริง
- **คำถาม:** เครื่องเดิมที่รุ่นไม่ตรงกับข้อมูลหลักแบบตัวต่อตัว (เช่น สะกดต่าง "HF78HS" กับ "HF-78HS", รุ่นเดียวกันอยู่หลายหมวดหมู่, ประเภทเดิมขัดกับข้อมูลหลัก) จะให้แก้อย่างไร และอนุญาตให้รันกับข้อมูลจริงเมื่อใด
- **ทาง A:** ระบบจับคู่เฉพาะที่ตรงตัวชุดเดียว (ทำแล้ว ทดสอบใน QA) · ที่เหลือส่งรายงาน (CSV) ให้ลูกค้าระบุทีละรายการ แล้วรันอีกรอบ
- **ทาง B:** ไม่ย้ายข้อมูลเดิม ใช้ข้อมูลหลักเฉพาะเครื่องใหม่ เครื่องเดิมแก้ทีละเครื่องเมื่อมีงาน
- **SA แนะนำ:** A — รันแบบอ่านอย่างเดียว (dry-run) กับสำเนาข้อมูลจริงก่อน ให้ลูกค้าเห็นตัวเลข MATCHED / AMBIGUOUS / CONFLICT / UNMAPPED แล้วค่อยตัดสินใจ
- **ผลต่อข้อมูลเดิม:** A เติมประเภท/หมวดหมู่ที่ว่าง + อ้างรุ่นในข้อมูลหลัก (ไม่แก้ชื่อรุ่นเดิม · มี backup และ rollback) · B ไม่แก้
- **ผลต่อการทำงาน:** A ตัวกรองและรายงานใช้ได้กับเครื่องเดิม · B เครื่องเดิมไม่มีประเภท/หมวดหมู่จนกว่าจะแก้
- **ความเสี่ยง:** จับคู่ผิด = ข้อมูลเครื่องผิด (ลดด้วยตรงตัวเท่านั้น + rollback)
- **กัน UAT:** เฉพาะ scenario ที่ใช้เครื่องเดิม · **เลื่อนได้:** ได้

### 2. D-11 — ขั้นจ่ายเงิน / ยืนยันรับเงิน / วางบิล / เช่าซื้อ
- **คำถาม:** หลังปิดงาน ต้องมีขั้นจ่ายเงินและช่างยืนยันรับเงินก่อนวางบิลหรือไม่ · กรณีไม่อนุมัติทำอย่างไร · งานเช่าซื้อ: สถานะเครื่อง ผู้ถือกรรมสิทธิ์ รายรับ ประกัน
- **ทาง A:** ใช้ขั้นวางบิลเดิมทั้งหมดใน UAT รอบแรก แล้วออกแบบขั้นใหม่แยก
- **ทาง B:** เพิ่มขั้นตามที่ลูกค้าระบุ (ต้องได้รายการสถานะ ผู้กระทำ และเงื่อนไขครบ)
- **SA แนะนำ:** A สำหรับ UAT รอบแรก
- **ผลต่อข้อมูลเดิม:** A ไม่กระทบ · B อาจต้องตั้งสถานะให้บิลเดิม
- **ผลต่อการทำงาน:** ข้ออื่นที่รอข้อนี้: เช่าซื้อด้านการเงิน (D-09) · ขั้น "Admin ยืนยันปิดงาน" แยกจากการปิดงาน (D-16) · จังหวะบันทึกต้นทุนเมื่อเปิดงานจากใบเสนอราคา (D-18)
- **ความเสี่ยง:** การเงิน — ถ้าทำโดยไม่มีกติกา ยอดรับรู้รายได้/สถานะเครื่องเช่าซื้อผิด
- **กัน UAT:** ใช่ สำหรับ scenario การเงินและเช่าซื้อ · **เลื่อนได้:** ได้ ถ้าตัด scenario เหล่านี้ออกจาก UAT รอบแรก

### 3. D-22 — Sale เห็นรายรับ/ต้นทุนรายใบงาน
- **คำถาม:** Sale ควรเห็นยอดเงินรายใบงาน (และราคามาตรฐานในข้อมูลหลักรุ่นเครื่อง) หรือไม่
- **ทาง A (ทำอยู่):** ไม่เห็น — เห็นเฉพาะ CEO / Admin / Manager / Viewer
- **ทาง B:** Sale เห็นยอดเงินของใบงาน
- **SA แนะนำ:** A
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ · **ผลต่อการทำงาน:** Sale ไม่เห็นตัวเลขเงิน (หน้าเว็บเดิมก็ไม่แสดง)
- **ความเสี่ยง:** B = ข้อมูลการเงินเปิดกว้างขึ้น
- **กัน UAT:** ไม่ · **เลื่อนได้:** ได้

### 4. D-23 — แก้รายการชำระของสัญญาที่ชำระครบ เมื่อเครื่องมีสัญญาใหม่
- **คำถาม:** ถ้ายกเลิกรายการชำระที่บันทึกผิด แล้วสัญญาเดิมจะกลับเป็น "ใช้งานอยู่" ขณะเครื่องมีสัญญาใหม่ ควรทำอย่างไร
- **ทาง A (ทำอยู่):** ปฏิเสธ พร้อมบอกเลขสัญญาใหม่ — ต้องจัดการสัญญาใหม่ก่อน
- **ทาง B:** ยอมแก้ยอด แต่คงสถานะ "ชำระครบ" และสร้างรายการติดตามยอดค้างแยก
- **SA แนะนำ:** A
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ · **ผลต่อการทำงาน:** บัญชีแก้เองไม่ได้ในกรณีนี้
- **ความเสี่ยง:** B ต้องออกแบบเพิ่ม · A ไม่มีข้อมูลเสีย
- **กัน UAT:** ไม่ · **เลื่อนได้:** ได้

### 5. Q-R3-01 — CEO อนุมัติ/ส่งตาราง PM
- **คำถาม:** คำตอบเดิม (VFB แถว 21) ให้ CEO อนุมัติตาราง PM ได้ แต่ D-01 ระบุว่า CEO ไม่ได้สิทธิ์อนุมัติของ Manager โดยอัตโนมัติ — CEO ควรอนุมัติตาราง PM ได้หรือไม่
- **ทาง A (ทำอยู่):** ได้ — ตามคำตอบ VFB แถว 21 (CEO ยังอนุมัติคำขอแก้ไขข้อมูลไม่ได้)
- **ทาง B:** ไม่ได้ — CEO ดูอย่างเดียวทุกเรื่อง อนุมัติตาราง PM เป็นของ Manager
- **SA แนะนำ:** B ถ้าลูกค้าต้องการให้ CEO เป็นผู้ดูอย่างเดียวจริง · ถ้า CEO ต้องการเป็นผู้อนุมัติตาราง PM ให้คง A
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ (ตารางที่อนุมัติแล้วคงเดิม) · **ผลต่อการทำงาน:** B — Manager ต้องอนุมัติเองทุกเดือน
- **ความเสี่ยง:** A — มีผู้อนุมัติ 2 บทบาท
- **กัน UAT:** ไม่ (เฉพาะ scenario สิทธิ์ CEO) · **เลื่อนได้:** ได้

### 6. Q-R3-10 — แก้วิธีคิดมูลค่าสต๊อกต้องขออนุมัติหรือไม่
- **คำถาม:** Admin แก้วิธีคิดมูลค่าสต๊อกได้ทันที (พฤติกรรมเดิม) ขณะที่หัวเอกสารต้องขออนุมัติ Manager — ต้องเหมือนกันหรือไม่
- **ทาง A (ทำอยู่):** Admin แก้ได้ทันที · **ทาง B:** ส่งคำขอให้ Manager อนุมัติ
- **SA แนะนำ:** B — วิธีคิดมูลค่ากระทบรายงานมูลค่าสต๊อกทั้งบริษัท
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ · **ผลต่อการทำงาน:** B เพิ่มขั้นอนุมัติ (เปลี่ยนไม่บ่อย)
- **ความเสี่ยง:** A — มูลค่าสต๊อกเปลี่ยนโดยไม่มีผู้ตรวจ
- **กัน UAT:** ไม่ · **เลื่อนได้:** ได้

### 7. Q-R3-12 (N3) — ยกเลิกงานติดตั้ง ขณะสัญญามีผลแล้ว
- **คำถาม:** สัญญาเช่า/ขายมีผลแล้ว แต่งานติดตั้งถูกยกเลิก (หรือถอดเครื่องออกจากงาน) — ตอนนี้เครื่องคง "ในคลัง" และระบบไม่แจ้งใคร ควรทำอย่างไร
- **ทาง A:** แจ้ง Admin/เซลล์เจ้าของสัญญาให้เปิดงานติดตั้งใหม่หรือยกเลิกสัญญา · เครื่องคง "ในคลัง"
- **ทาง B:** ห้ามยกเลิกงานติดตั้ง/ถอดเครื่อง ถ้ามีสัญญาที่มีผลกับเครื่องนั้น จนกว่าจะจัดการสัญญา
- **SA แนะนำ:** A — ไม่บล็อกงานหน้างาน แต่ไม่ให้ข้อมูลค้างโดยไม่มีคนรู้
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ (ตรวจย้อนหลังได้ด้วยรายงาน)
- **ผลต่อการทำงาน:** A เพิ่มการแจ้งเตือน · B Admin ต้องจัดการสัญญาก่อน
- **ความเสี่ยง:** ปัจจุบัน — สัญญาเรียกเก็บเงินกับเครื่องที่ยังไม่ติดตั้ง โดยไม่มีใครเห็น
- **กัน UAT:** ไม่ · **เลื่อนได้:** ได้

### 8. Q-R3-13 — แก้ข้อมูลหลังปิดงาน และการเซ็นใหม่ (D-16)
- **คำถาม:** D-16 อนุมัติว่า "หลัง Admin ยืนยันปิดงาน การแก้ต้องได้รับอนุญาต และถ้าข้อมูลที่ลงนามเปลี่ยนต้องเซ็นใหม่" — ใครอนุญาต และใครเป็นผู้เซ็นใหม่ (ลูกค้า/ช่าง/Admin)
- **ทาง A (ทำอยู่):** หลังปิดงานแก้ไม่ได้ทุกกรณี (เข้มกว่ากติกา) · ก่อนปิดงานแก้ได้ และลายเซ็นตอนปิดครอบคลุมข้อมูลสุดท้าย
- **ทาง B:** Manager อนุมัติการแก้หลังปิด · ลายเซ็นเดิมถูกทำเครื่องหมาย "ข้อมูลเปลี่ยนหลังลงนาม" และช่างเซ็นยืนยันใหม่ (ลูกค้าไม่ต้องเซ็นใหม่)
- **SA แนะนำ:** B เมื่อ D-11 ชัดเจน (การแก้หลังปิดกระทบบิล)
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ · **ผลต่อการทำงาน:** A — ข้อมูลผิดหลังปิดแก้ไม่ได้
- **ความเสี่ยง:** B กระทบบิลที่วางแล้ว
- **กัน UAT:** ไม่ · **เลื่อนได้:** ได้

### 9. Q-R3-03 — ช่างเห็นเครื่องของใบงานที่ถูกยกเลิก

### 12. Q-R3-11 — ยกเลิกใบเสนอราคาที่ผูกใบงานแล้ว
- **คำถาม:** ใบเสนอราคาที่ผูกกับใบงานแล้ว ถูกยกเลิก/ปฏิเสธภายหลัง — ให้ปลดการผูกอัตโนมัติ หรือห้ามยกเลิกจนกว่าจะปลด
- **ทาง A (ทำอยู่):** ยกเลิกได้ และยังผูกอยู่ · **ทาง B:** ปลดการผูกพร้อมบันทึกประวัติ · **ทาง C:** ห้ามยกเลิกจนกว่าจะปลด
- **SA แนะนำ:** C — ป้องกันใบงานอ้างใบที่ยกเลิก
- **ผลต่อข้อมูลเดิม:** ไม่กระทบ · **กัน UAT:** ไม่ · **เลื่อนได้:** ได้

### 13. Q-R3-14 — ราคามาตรฐานสองแหล่ง (ผู้ตรวจอิสระจัดเป็นระดับสูง: ADV3-01)
- **คำถาม:** หน้า "รุ่นเครื่อง (ข้อมูลหลัก)" (D-07A) มีราคามาตรฐานต่อ ประเภท+หมวดหมู่+รุ่น (ตัวอย่างของลูกค้า 2,000 บาท) ส่วนการคิดรายรับติดตั้งในหน้ากำไรรายเครื่องยังใช้ราคาของรุ่นใน Model Index เดิม — ราคา 2,000 ของลูกค้าคือ "ค่าติดตั้งมาตรฐาน" ที่ต้องใช้คิดรายรับใช่หรือไม่
- **สถานะตอนนี้:** เมื่อเพิ่มรุ่นใหม่ในข้อมูลหลัก ระบบเพิ่มชื่อรุ่นใน Model Index ให้ด้วย แต่ราคาใน Model Index เป็น 0 จนกว่าจะมีคนตั้ง → รายรับติดตั้งของรุ่นใหม่จะเป็น 0 · ระบบไม่คัดลอกราคาเอง เพราะเป็นการเปลี่ยนวิธีคิดตัวเลขการเงินที่ยังไม่ได้อนุมัติ
- **ทาง A:** ราคาในข้อมูลหลักรุ่นเครื่องเป็นแหล่งเดียวของรายรับติดตั้ง (ต้องกำหนดกรณีรุ่นเดียวกันอยู่หลายหมวดหมู่ เช่น "IM-220A + B-301") · **ทาง B:** คง Model Index เป็นแหล่งรายรับ ราคาในข้อมูลหลักใช้แสดง/เติมค่าในฟอร์มเท่านั้น (ทำอยู่) และให้ผู้ดูแลตั้งราคาใน Model Index เอง
- **SA แนะนำ:** A ตัดสินพร้อม D-11 · ระหว่างรอใช้ B และตั้งราคาใน Model Index ของรุ่นที่ใช้งานจริงให้ครบก่อน UAT
- **ผลต่อข้อมูลเดิม:** A ต้องเทียบราคาสองแหล่ง (รายงานความต่างได้) และอาจเปลี่ยนตัวเลขกำไรย้อนหลังของรายงาน · B ไม่เปลี่ยน
- **ผลต่อการทำงาน:** A ผู้ดูแลแก้ราคาที่เดียว · B ต้องดูแลสองที่ และตัวเลขอาจไม่ตรงกัน
- **ความเสี่ยงการเงิน:** สูง — รายรับติดตั้งของรุ่นใหม่เป็น 0 หรือไม่ตรงกับราคาที่ลูกค้าคาด
- **กัน UAT:** เฉพาะ scenario ที่ตรวจรายรับติดตั้ง/กำไรรายเครื่อง · **เลื่อนได้:** ได้ ถ้าลูกค้าลงนามว่าไม่ตรวจตัวเลขรายรับติดตั้งใน UAT รอบแรก

## เรื่องที่ไม่ต้องตัดสินใจแล้ว (เพื่ออ้างอิง)
- ADV-11b ป้ายเครื่องใช้ 4 ตัวท้ายของรหัสภายใน — D-19 อนุมัติแล้ว
- Q-R3-06 (แชทรายใบงาน), Q-R3-08 (PM เครื่องที่ไม่ได้ทำใช้วิธีถอดเครื่อง), Q-R3-09 (บันทึกย้อนหลังแบบมีสิทธิ์) — ไม่ได้อยู่ในขอบเขตที่อนุมัติ ไม่กระทบ UAT · ถ้าต้องการให้แจ้งเป็นความต้องการใหม่
