# ADV3-01 — ราคา/ต้นทุนมาตรฐาน: การกระทบยอดหลังการตัดสินใจของเจ้าของโครงการ (30 ต.ค. 69 ค่ำ)

ระดับ: **High — ยังเปิด** ในขอบเขตรายรับติดตั้ง/กำไรรายเครื่อง (ไม่ลดระดับ)

## 1. แยกประเด็นตาม directive
| ส่วน | สถานะ |
|---|---|
| **ความกำกวมทางธุรกิจ (ปิดแล้ว):** 2,000 บาทใน 6 รุ่นตัวอย่างคืออะไร | เจ้าของยืนยัน: **ต้นทุนมาตรฐาน (Standard Cost)** ไม่ใช่ค่าติดตั้ง/ราคาขาย/รายรับ |
| **ที่ยังต้องยืนยัน:** แหล่งและกติกาอนุมัติ **ค่าติดตั้ง (Installation Charge)** | ระบบใช้ Model Index ตามโครงสร้างข้อกำหนด (IDX-01 / MAR-01) แต่ค่าและผู้อนุมัติยังไม่ยืนยันจากลูกค้า → ตัวเลขรายรับติดตั้ง/กำไรติดสถานะ "ยังไม่ยืนยัน" (10 R-01) |

ปิด ADV3-01 ได้เมื่อ: ยืนยันแหล่ง/ค่า/กติกาอนุมัติค่าติดตั้ง + รัน `standard-cost:reconcile` บนข้อมูล UAT และทบทวนผล + หลักฐาน regression ของการคำนวณ (มีแล้วใน QA)

## 2. แก้ไขจากการตีความเดิม (Q-R3-14 controlled A ซึ่งถูกแทน)
เดิม (โค้ดก่อน 30 ต.ค. ค่ำ): ราคาใน Equipment Model Master เป็น "ราคาติดตั้งมาตรฐาน" ใช้คิดรายรับงานใหม่ · 2,000 ถูกเก็บเป็น "ยังไม่อนุมัติ" จึงยังไม่เคยถูกคิดเป็นรายรับ (ไม่มีตัวเลขย้อนหลังที่ต้องแก้) · ฟีเจอร์นี้ยังไม่เคย deploy → ไม่มีข้อมูลจริงที่ต้อง migrate

ใหม่:
| เรื่อง | การทำงาน |
|---|---|
| ต้นทุนมาตรฐาน | Equipment Model Master (ฐาน: `standardPrice` · API: `standardCost`) · อนุมัติ/ประวัติเหมือนเดิม (ความหมายเป็นต้นทุน) · เห็นเฉพาะผู้มี `parts:cost_view` (Admin/Manager) — CEO/ACC/Viewer/Sale/ช่างได้ `null` / 403 ประวัติ · 6 รุ่นตัวอย่าง seed เป็น "อนุมัติ" โดย `owner-directive-2026-10-30` · ไม่ใช้ 2,000 กับรุ่นอื่น |
| snapshot ในรายการเครื่องของใบงาน | `standardCostSnapshot` (ต้นทุน ณ วันเพิ่มเครื่อง) · `priceSnapshot` เดิม (มีเฉพาะข้อมูล QA) อ่านเป็นต้นทุน ไม่เคยเป็นรายรับ |
| ค่าติดตั้ง | `installChargeSnapshot` จาก Model Index ณ วันเพิ่มเครื่อง (`verified:false`) · แก้ Model Index ภายหลังไม่เปลี่ยนรายการที่ capture แล้ว · ยังไม่มีค่า = อ่านค่าปัจจุบันทุกครั้ง (`MODEL_INDEX_UNCAPTURED`) และ Manager capture ได้ (`capture-install-charge`, มี log) · อ่านไม่ได้ = `ERROR` ไม่ใช่ "ไม่มีราคา" · ไม่มีค่า = แสดงเหตุผล ไม่คิดเป็น 0 |
| รายการเดิม (ก่อน Q-R3-14) | คิดจาก Model Index ปัจจุบันเหมือนเดิมทุกตัวเลข (ไม่คำนวณย้อนหลังใหม่) + ป้ายข้อมูลเดิม |
| กำไร | MAR-03 เดิม: รายรับ (ค่าติดตั้ง − ส่วนลดรายเครื่อง + บรรทัดใบเสนอราคาที่ตอบรับ) − (ค่าบริการช่าง + ส่วนแบ่งค่าใช้จ่ายร่วม + อะไหล่ที่ใช้รายเครื่อง) · ต้นทุนมาตรฐานไม่เข้ากำไร · `installChargeVerified:false` · `profitVerified` จริงได้เฉพาะเมื่อไม่มีรายรับติดตั้งที่ยังไม่ยืนยัน/ขาด/ถูกซ่อน |
| ใบเสนอราคา | ไม่เก็บ/ไม่ส่งต้นทุนในบรรทัด (คงแค่ `modelMasterId`) · snapshot เดิมถูกตัดออกจาก API/PDF/Excel · `unitPrice` ไม่ถูกเติมจากต้นทุน |
| endpoint เดิม `apply-install-price` | 410 ไม่เขียนอะไร · ใช้ `apply-standard-cost` (Manager) เติมต้นทุนที่ขาด ไม่กระทบรายรับ |

## 3. รายงานกระทบยอด (อ่านอย่างเดียว)
`npm run standard-cost:reconcile -- --out <dir>` (alias `install-price:reconcile`) → CSV + JSON ต่อ ประเภท+หมวดหมู่+รุ่น: ต้นทุนมาตรฐาน (+สถานะ) เทียบค่าติดตั้งใน Model Index (+ไม่มีค่า) · รุ่นหลายหมวดหมู่ · จำนวนรายการเครื่องที่มี/ไม่มี snapshot แต่ละชนิด · `withLegacyPriceSnapshotOnly`

ผลบนฐาน QA: `evidence/final-run-17/` (cost-reports) และการซ้อม UAT `evidence/uat-rehearsal-final/reconcile/` · **บนข้อมูล UAT: ยังไม่ได้รัน** (ต้องมีสิทธิ์เข้า Atlas — runbook ข้อ 2, 4.4)
