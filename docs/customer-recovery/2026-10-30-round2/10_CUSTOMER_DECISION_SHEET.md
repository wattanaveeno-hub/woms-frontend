## รายละเอียด — ข้อที่ต้องตอบก่อน (P0 / P1)

### D-03 · ข้อมูล "ของตนเอง" ของช่าง — **P0**
1. **ต้องตัดสิน:** ช่างเห็นเครื่อง แผนที่ สต๊อก อะไหล่ และประวัติ ได้แค่ไหน
2. **ทำไมสำคัญ:** เดิมช่างเรียกข้อมูลทั้งบริษัทผ่าน API ได้ (BUG-V2-17) · Round 2 ปิดไว้ชั่วคราวแล้ว ต้องให้ลูกค้ารับรองว่าไม่ปิดเกินจนช่างทำงานไม่ได้
3. **ทาง A (ที่ทำไว้ชั่วคราว):** เครื่อง/แผนที่ = เครื่องในใบงานที่ได้รับมอบหมาย (ไม่รวมใบงานที่ยกเลิก) + ตาราง PM ที่ส่งให้แล้ว · คิวที่รับผิดชอบเห็นเฉพาะรุ่นเครื่อง ไม่เห็น SN/ประวัติเครื่อง (TECH-02) · หมายเหตุ: หน้ารายการเครื่องในใบงานที่ยกเลิกยังแสดง SN ตามสิทธิ์ใบงานเดิม — ลูกค้าต้องเลือกว่าจะปิดด้วยหรือไม่ · สต๊อก = คลังรถของตนเท่านั้น ไม่เห็นคลังกลางและต้นทุน · ข้อมูลอะไหล่ = รหัส/ชื่อ/รุ่น ไม่มีราคา
4. **ทาง B:** เหมือน A แต่ให้เห็นยอดคงเหลือคลังกลาง (ไม่มีต้นทุน) เพื่อวางแผนเบิก
5. **SA แนะนำ:** B ถ้าช่างต้องเช็กของในคลังกลางก่อนออกงาน · ไม่เช่นนั้น A
6. **ผลต่อข้อมูลเดิม:** ไม่แก้ข้อมูล · ใบงานเก่าที่ไม่มี technicianIds ช่างจะไม่เห็นเครื่องในงานนั้น (ตรวจจำนวนได้จาก preflight PF-07/PF-10)
7. **ผลต่อการทำงาน:** ช่างไม่เห็นยอดคลังกลางก่อนเบิก (ระบบยังตรวจยอดตอนเบิก) · ไม่เห็นภาพรวมคลังเครื่องทั้งบริษัท
8. **กัน UAT:** ใช่ (ต้องรับรองนโยบายก่อนให้ช่างทดสอบ)
9. **ขึ้นกับ:** ไม่มี

### D-01 · การจับคู่บทบาท Admin Service / CEO / Manager — **P1**
1. ต้องตัดสิน: "Admin Service" คือบทบาท admin หรือไม่ · CEO กับ Manager เห็นเมนูต่างกันอย่างไร
2. สำคัญเพราะ: กำหนดว่าใครเห็นแดชบอร์ด/ตั้งค่า (NAV-01, AUTH-01)
3. A: Admin Service = admin · CEO ดูทุกอย่าง+อนุมัติ ไม่แก้ไข (ตามที่ลูกค้าตอบใน VFB แถว 21)
4. B: แยกบทบาท Admin Service ใหม่ (ต้องพัฒนาเพิ่ม)
5. SA แนะนำ: A
6. ข้อมูลเดิม: ไม่กระทบ · 7. การทำงาน: ไม่เปลี่ยนจากปัจจุบัน
8. กัน UAT: เฉพาะ scenario เมนู/แดชบอร์ด · 9. ขึ้นกับ: —

### D-05 · ช่องบังคับและการวางข้อความในหน้าเปิดคิว (QUE-02) — **P1**
1. ต้องตัดสิน: ช่องใดบังคับ · ต้องมีกล่องวางข้อความแล้วตรวจก่อนบันทึกหรือไม่
2. สำคัญเพราะ: QUE-02 ตรวจรับไม่ได้จนกว่าจะมีรายการช่องบังคับ
3. A: บังคับ ประเภทงาน(+ย่อย) · ลูกค้าหรือชื่อร้าน · ผู้ติดต่อ+เบอร์ · ที่อยู่หรือสาขา · เครื่อง ≥1 · รายละเอียดเมื่อเลือก "อื่น ๆ"
4. B: บังคับเท่าปัจจุบัน (ประเภทงาน/ชื่อร้าน/เครื่อง) + กล่องวางข้อความ
5. SA แนะนำ: A + กล่องวางข้อความใช้ตัวแยกข้อความแบบเดียวกับหน้าเปิดงาน
6. ข้อมูลเดิม: คิวเดิมที่ขาดช่องไม่ถูกบังคับย้อนหลัง · 7. การทำงาน: เซลล์กรอกมากขึ้น
8. กัน UAT: scenario QUE-02 · 9. ขึ้นกับ: —

### D-06 · รูปแบบรหัสลูกค้า (≤ 4 หลัก) — **P1**
1. ต้องตัดสิน: ตัวเลขล้วนหรือมีตัวอักษร · รหัสเดิม 5 ตัว (เช่น I2228, IR084) ทำอย่างไร
2. สำคัญเพราะ: ข้อกำหนดขัดกับรหัสจริงที่ใช้อยู่
3. A: บังคับ ≤4 เฉพาะรหัสใหม่ เก็บเป็นข้อความ (รักษาเลขศูนย์นำหน้า) รหัสเดิมคงไว้
4. B: แปลงรหัสเดิมทั้งหมด (ต้องมี migration + ตารางเทียบรหัส)
5. SA แนะนำ: A
6. ข้อมูลเดิม: A ไม่แก้ · B แก้ทุกเอกสารที่อ้างรหัส · 7. การทำงาน: A รหัสสองรูปแบบอยู่ร่วมกัน
8. กัน UAT: scenario QUE-03 ส่วนรหัส · 9. ขึ้นกับ: —

### D-07 · ประเภทเครื่อง–รูปแบบ–รุ่น (EQ-01/02, FB-20) — **P1**
1. ต้องตัดสิน: mapping ประเภท (ตู้ฟรีส/ตู้แช่/เครื่องทำน้ำแข็ง) → รูปแบบ → รุ่น
2. สำคัญเพราะ: ต้องแก้ master และข้อมูลเครื่องเดิม
3. A: Dev ส่งรายการรุ่นปัจจุบันให้ลูกค้ากรอก mapping แล้วทำ migration (dry-run + backup + rollback)
4. B: ใช้เฉพาะเครื่องใหม่ เครื่องเดิมแก้ทีละเครื่อง
5. SA แนะนำ: A
6. ข้อมูลเดิม: แก้ฟิลด์ machineType/รูปแบบของเครื่องเดิม (ต้องอนุมัติ migration) · 7. การทำงาน: ตัวเลือกในหน้าเปิดคิว/งานเปลี่ยน
8. กัน UAT: scenario EQ-01/02 · 9. ขึ้นกับ: ลูกค้ากรอกตาราง mapping

### D-11 · ขั้นจ่ายเงิน/ยืนยันรับเงิน/วางบิล (WF-01 ข้อ 8, WF-02) — **P1**

### D-22 (ใหม่) · Sale เห็นรายรับ/ต้นทุนรายใบงาน — **ทำแล้ว รอยืนยัน**
1. ต้องตัดสิน: Sale ควรเห็น revenue/cost ของใบงานหรือไม่

3. A (ที่ทำไว้ชั่วคราว): เฉพาะผู้ดูเอกสารขายได้ (CEO/Admin/Manager/viewer) เห็นยอดเงินใบงาน · B: ให้ Sale เห็นด้วย
4. SA แนะนำ: A · ข้อมูลเดิม: ไม่กระทบ · การทำงาน: Sale/ช่างไม่เห็นตัวเลขเงินใบงาน (หน้าเว็บเดิมก็ไม่แสดง) · กัน UAT: ไม่ (ทำแล้ว รอยืนยัน) · ขึ้นกับ: D-01

### D-23 (ใหม่) · แก้/ยกเลิกรายการชำระของสัญญาที่ชำระครบแล้ว เมื่อเครื่องมีสัญญาฉบับใหม่ — **ทำแล้ว รอยืนยัน**
1. **ต้องตัดสิน:** ถ้า Manager ยกเลิกรายการชำระที่บันทึกผิดของสัญญาที่ "ชำระครบ" แล้ว ระบบดึงสัญญากลับเป็น "ใช้งานอยู่" — ถ้าเครื่องนั้นมีสัญญาฉบับใหม่ที่ใช้งานอยู่ ควรทำอย่างไร
2. **ทำไมสำคัญ:** ผู้ตรวจอิสระพบว่าเส้นทางนี้ทำให้เครื่องเดียวมีสัญญาใช้งาน 2 ฉบับ (R2-F15) · Round 2 ปิดไว้แล้วตามทาง A
3. **ทาง A (ที่ทำไว้):** ปฏิเสธการแก้รายการชำระ พร้อมข้อความบอกเลขสัญญาฉบับใหม่ — ต้องจัดการสัญญาฉบับใหม่ก่อน
4. **ทาง B:** ยอมให้แก้ยอด แต่คงสถานะ "ชำระครบ" และสร้างรายการติดตามยอดค้างแยก (ต้องออกแบบเพิ่ม)
5. **SA แนะนำ:** A — ไม่มีข้อมูลเสีย กรณีนี้เกิดน้อย
6. **ผลต่อข้อมูลเดิม:** ไม่กระทบ
7. **ผลต่อการทำงาน:** บัญชี/Manager แก้รายการชำระเองไม่ได้ในกรณีนี้ ต้องจัดการสัญญาฉบับใหม่ก่อน
8. **กัน UAT:** ไม่
9. **ขึ้นกับ:** —
